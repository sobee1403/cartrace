## 1. 제안 요약

스마트 중고차 수출 ERP 시스템은 중고차 수출 과정에서 차량 한 대를 하나의 업무 레코드로 관리하고, 영업팀의 처리 속도와 회계팀의 리스크 통제를 동시에 만족시키는 운영 시스템이다. 구현 패키지명은 `cartrace`로 유지한다.

핵심은 모든 문제를 무조건 차단하는 것이 아니다.

- 되돌릴 수 없는 손해는 거래 단계에서 막는다.
- 선적 후에 발생하는 증빙은 미결과 기한으로 관리한다.
- 회계팀이 확인해야 할 불일치는 거래가 발생하는 순간에 발견한다.
- 상태 변경 화면에는 담당자·시각·사유를 남긴다. 이번 가안에서는 정적 타임라인으로 표현한다.

## 2. 영업 총괄과 회계팀장을 동시에 설득하는 비즈니스 로직

### 2.1 권리 이상은 선적 전 하드 게이트로 차단

VIN을 기준으로 매입 전과 선적 직전에 권리 상태를 각각 조회한다.

- 압류·저당·도난·소유권 문제 발견
- 활성 재고 내 동일 VIN 발견
- 소유권 확보 전 선적 시도

위 조건은 선적 버튼을 비활성화한다. 버튼 옆에는 차단 이유와 해제 조건을 표시한다.

영업팀에는 “왜 지금 못 보내는지”를 즉시 보여주고, 회계팀에는 되돌릴 수 없는 손해가 발생하기 전에 통제했다는 근거를 제공한다.

### 2.2 매입 증빙·금액·환율 언밸런스 크로스체크

매입 유형과 수출 거래 단계에 따라 필요한 증빙과 검증 기준을 계산한다. 매출 유형은 과제 범위상 수출로 고정한다.

- 매입 유형: 딜러·개인·경매
- 매입 증빙 방식: 현금·계좌이체·계산서 등
- 수출 데이터: 인보이스 외화 금액·적용 환율·환산 원화 금액·수출신고 금액

다음 값을 비교한다.

```text
계약 금액 ↔ 실제 지급액
인보이스 외화 금액 × 적용 환율 ↔ 수출신고 원화 금액
매입 유형 ↔ 필수 매입 증빙
수출 거래 단계 ↔ 필수 수출·세무 증빙
차량 VIN ↔ 권리 조회·재고 레코드
```

정상 환율 차이와 실제 오류를 구분하기 위해 외화 금액, 적용 환율, 환율 기준일, 환산 원화 금액을 별도 필드로 저장한다.

### 2.3 선적은 허용하되 사후 증빙을 강제

B/L, 외화 입금증명처럼 선적 또는 결제 이후에만 생기는 서류를 선적 전 필수 조건으로 만들지 않는다.

대신 다음과 같이 처리한다.

1. 선적 전: 권리·소유권·수출신고 수리 여부를 하드 게이트로 검증한다.
2. 선적 직후: B/L·외화 입금증명·세무 증빙을 미결 항목으로 생성한다.
3. 미결 항목: 담당자·기한·미처리 시 영향·에스컬레이션 상태를 기록한다.
4. 기한 초과: 다음 수출 계약 또는 해당 차량의 후속 처리를 잠근다.

이 방식은 영업의 선적 속도를 보장하면서 회계팀의 사후 회수 가능성을 확보한다.

### 2.4 미결을 단순 알림이 아니라 회수 장치로 사용

알림은 다음 정보를 반드시 포함한다.

```text
무엇이 / 어느 차량에서 / 왜 / 담당자 / 남은 기한 / 미처리 시 잠기는 업무
```

예시:

| 상황 | 처리 방식 | 영향 |
| --- | --- | --- |
| 계약 금액과 입금액 불일치 | D+1까지 담당자 검토 요청 | 매입 확정 보류 |
| 선적 후 B/L 미첨부 | 선적 후 7~14일 기한 부여 | 다음 수출 계약 잠금 |
| 외화 입금증명 미첨부 | 담당자·회계팀장 확인 요청 | 환급 관련 증빙 검토 지연 |
| 권리 이상 발견 | 즉시 하드 게이트 | 선적 차단 |
| 동일 VIN 등록 시도 | 신규 등록 거부 | 중복 매입 방지 |

## 3. 데이터와 상태 설계

### 화면에 표시할 핵심 상태

```text
매입 → 재고 → 수출 준비 → 선적 → 증빙
```

상세 업무 단계와 도메인 지식은 비공개 참고 문서에 보관하고, 제출 화면에서는 5개 매크로 단계로 단순화한다. 상태와 위험 플래그는 분리한다. 한 차량이 `수출 준비` 또는 `선적` 단계이면서 `저당 발견`, `B/L 미첨부` 플래그를 동시에 가질 수 있어야 한다.

### 핵심 데이터

- 차량: 내부 ID, VIN, 차종, 연식, 매입 유형, 수출 거래 상태
- 매입: 계약 금액, 지급액, 지급일, 상대방
- 수출: 구매자, 국가, 인보이스, 통화, 환율, 수출신고 금액
- 권리 조회: 결과, 출처, 조회자, 조회 시각
- 증빙: 문서 유형, 필수 여부, 첨부 상태, 기한
- 알림: 유형, 담당자, 기한, 에스컬레이션 상태
- 상태 타임라인: 이전 상태, 변경 상태, 변경자, 변경 시각, 사유

## 4. 기획안의 결론

스마트 중고차 수출 ERP 시스템은 영업팀의 거래를 무조건 막는 시스템이 아니라, 막아야 할 위험과 나중에 회수할 수 있는 미결을 구분하는 시스템이다.

> 되돌릴 수 없는 손해는 막고, 돈으로 메울 수 있는 손해는 빚으로 남겨 다음 거래에서 회수한다.
