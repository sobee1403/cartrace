# 스마트 중고차 수출 ERP 시스템 핵심 기능 및 화면 범위

## 1. 화면 설계 원칙

스마트 중고차 수출 ERP 시스템의 화면은 지표를 보여주는 데서 끝나지 않고, 사용자가 다음 행동을 바로 판단할 수 있게 설계한다.

- 무엇이 문제인가?
- 어느 차량에서 발생했는가?
- 왜 문제가 생겼는가?
- 누가 언제까지 처리해야 하는가?
- 지금 막아야 하는가, 미결로 남겨도 되는가?
- 처리하지 않으면 다음에 무엇이 잠기는가?

## 2. 핵심 기능

### 2.1 차량 단위 업무 레코드

차량 한 대를 하나의 업무 레코드로 관리한다.

- 차량 기본 정보와 VIN
- 매입 유형과 매입 계약
- 지급 상태와 실제 지급액
- 수출 계약과 인보이스
- 환율과 원화 환산액
- 권리 조회 결과
- 증빙 체크리스트
- 현재 상태와 상태 변경 이력
- 담당자와 미결 알림

### 2.2 업무 상태 관리

화면에서는 사용자가 빠르게 이해할 수 있도록 다음 5개 매크로 단계로 보여준다.

```text
매입 → 재고 → 수출 준비 → 선적 → 증빙
```

상세 업무 단계와 도메인 참고 지식은 비공개 문서에 보관한다. 상태와 위험 플래그는 분리한다. 예를 들어 차량이 `수출` 상태이면서 동시에 `저당 발견`과 `증빙 누락` 플래그를 가질 수 있어야 한다.

### 2.3 거래 유형별 증빙 체크리스트

매입 유형과 수출 거래 단계에 따라 필요한 증빙을 자동으로 계산한다. 매출 유형은 과제 범위상 수출로 고정한다.

- 매입 계약서
- 차량등록 관련 서류
- 매입 지급 증빙
- 인보이스
- 수출신고필증
- B/L
- 외화 입금증명
- 세무·환급 관련 증빙

증빙마다 다음 정보를 가진다.

- 필수 여부
- 현재 상태: 완료·대기·예외
- 담당자
- 제출 기한
- 미완료 시 잠기는 단계
- 첨부자와 첨부 시각

### 2.4 금액·환율 불일치 검증

다음 값을 분리해 저장하고 비교한다.

- 계약 금액
- 실제 지급액
- 인보이스 외화 금액
- 적용 환율
- 환율 기준일
- 환산 원화 금액
- 수출신고 금액
- 실제 외화 입금액

단순히 숫자가 다르다는 이유로 막지 않고, 환율 허용 범위와 비교 기준을 함께 표시한다.

### 2.5 권리·VIN 검증

- 활성 재고 내 VIN 중복 확인
- 매입 전 권리 1차 조회
- 선적 전 권리 2차 조회
- 압류·저당·도난 여부
- 소유권 확보 여부
- 조회자·조회 시각·조회 출처

권리 이상은 선적 하드 게이트로 연결한다.

### 2.6 미결·알림 관리

알림은 단순한 경고 메시지가 아니라 다음 구조로 만든다.

```text
무엇이 / 어느 차량에서 / 왜 / 담당자 / 남은 기한 / 미처리 시 영향
```

예시:

- 계약 금액과 입금액 불일치 → D+1까지 담당자 검토 → 매입 확정 보류
- 선적 후 B/L 미첨부 → 선적 후 7~14일 → 다음 수출 계약 잠금
- 권리 이상 발견 → 즉시 팀장 에스컬레이션 → 선적 차단
- 인보이스와 수출신고 금액 차이 → 환율 기준 확인 → 회계 검토 요청

## 3. 화면 범위

### 화면 1. 차량 목록

#### 목적

팀장이 전체 차량의 현재 상태와 위험을 빠르게 파악하는 화면이다.

#### 우선 처리 정보

- 선적이 막힌 차량
- 미증빙 차량
- 24시간 초과 미결
- 담당자 확인이 필요한 차량

#### 목록 컬럼

- 차량명·연식
- VIN
- 현재 단계
- 매입·수출 유형
- 위험 플래그
- 누락 증빙
- 담당자
- 최근 변경 시각
- 다음 액션

#### 필터

- 상태
- 담당자
- 매입 유형
- 수출 거래 단계
- 위험 플래그
- 미결 기한 초과 여부

#### 핵심 인터랙션

행을 클릭하면 차량 상세로 이동한다. 하드 게이트 차량은 빨간색 위험 플래그와 차단 사유를 표시하고, 미결 차량은 남은 기한과 담당자를 바로 보여준다.

### 화면 2. 차량 상세

#### 목적

회계팀과 영업팀이 한 차량의 거래 전체를 함께 검토하는 화면이다.

#### 상단 영역

- 차량명·VIN
- 현재 상태
- 매입·수출 유형
- 담당자
- 위험 플래그
- 다음 단계 액션 버튼

액션 버튼은 한 화면에 다음 단계 하나만 강조한다. 조건이 충족되지 않으면 버튼을 비활성화하고 바로 옆에 이유와 해제 조건을 표시한다.

#### 왼쪽 영역: 증빙 체크리스트

- 거래 유형별 필수 증빙
- 완료·대기·예외 상태
- 담당자
- 기한
- 첨부 버튼
- 미완료 시 영향

#### 오른쪽 영역: 검증 카드

- 계약 금액 vs 지급액
- 인보이스 외화 금액 vs 수출신고 원화 금액
- 적용 환율과 기준일
- 권리 조회 결과
- VIN 중복 여부
- 환급 리스크와 증빙 상태

#### 하단 영역: 상태 변경 이력

- 변경 전 상태
- 변경 후 상태
- 변경자
- 변경 시각
- 변경 사유
- 참고 문서 또는 조회 출처

### 화면 3. 미결·알림

#### 목적

팀장이 미결 업무를 우선순위와 기한 기준으로 처리하는 화면이다.

#### 우선 처리 정보

- 24시간 초과 미결
- 오늘 처리 필요
- 팀장 확인 필요
- 다음 거래 잠금 건수

#### 목록 컬럼

- 알림 유형
- 차량·VIN
- 발생 이유
- 담당자
- 1차 확인 팀: 영업팀·회계팀
- 남은 기한
- 미처리 시 영향
- 다음 액션
- 에스컬레이션 상태

#### 핵심 인터랙션

알림을 클릭하면 차량 상세의 관련 검증 카드 또는 증빙 항목으로 이동한다. 회계팀은 단순히 알림을 닫는 것이 아니라 검토 결과, 사유, 다음 처리일을 남긴다.

## 4. 기능 우선순위

### 1순위: 발표 시 반드시 동작해야 하는 기능

- 차량 목록에서 상태·위험·미결을 확인
- 차량 상세에서 증빙 체크리스트와 금액 검증 확인
- 조건 미충족 시 액션 버튼 차단
- 차단 사유를 버튼 옆에 표시
- 미결 목록에서 담당자·기한·영향 확인

### 2순위: 가안의 설득력을 높이는 기능

- 환율 기준일과 환산 금액 표시
- 권리 조회 이력 타임라인
- 상태 변경 타임라인
- 24시간 초과 에스컬레이션
- 다음 거래 잠금 안내

### 3순위: 실제 서비스 전환 시 검토할 기능

- 외부 권리 조회 API
- 환율 API
- 문서 업로드·OCR
- 사용자 권한 관리
- 실제 DB와 감사 로그 저장
- 알림 발송 연동

#### 향후 파일 유효성 검증

현재 과제 화면의 업로드는 실제 저장 없이 브라우저 상태만 `서류 구비 완료 · 검토 대기`로 바꾸는 Mock 동작이다. 파일 첨부만으로 매입 확정·선적·증빙 완료 상태로 자동 전이하지 않으며, 별도의 `승인 요청`과 검토 결과가 있어야 단계가 바뀐다. 실제 서비스에서는 업로드 직후 파일 자체가 해당 증빙에 유효한지 검증하는 단계를 추가한다.

- 증빙 종류별 허용 확장자·용량·페이지 수 검사
- 파일명과 차량 ID·VIN의 연결 여부 확인
- 문서 내부의 VIN, 계약번호, 금액, 날짜를 OCR 또는 문서 파서로 추출
- 증빙 종류에 필요한 필수 항목이 존재하는지 확인
- 인보이스·수출신고필증·B/L 간 VIN과 금액 교차검증
- 검증 실패 시 `확인 완료`로 바꾸지 않고 실패 사유와 재업로드 버튼 표시
- 검증 통과 시 업로드자·업로드 시각·검증 결과·파일 해시를 감사 이력에 기록

이 로직은 실제 외부 API·OCR·저장소 연동 범위에 해당하므로 과제 구현에서는 제외하고, 제품 확장 시의 후속 설계로 남긴다.

## 5. 화면으로 증명해야 하는 설계 포인트

1. **상태보다 다음 액션이 먼저 보여야 한다.** 사용자가 현재 위치를 파악한 뒤 무엇을 해야 할지 바로 알아야 한다.
2. **막힌 이유가 버튼 옆에 있어야 한다.** 사용자가 다른 화면을 찾아다니지 않도록 한다.
3. **알림은 기한과 책임자를 가져야 한다.** 경고만 있고 소유자가 없으면 업무가 움직이지 않는다.
4. **회계 검증은 차량 상세에 포함되어야 한다.** 별도 엑셀이나 사후 대조로 밀어내지 않는다.
5. **미결은 실패가 아니라 회수 계획이어야 한다.** 다음 거래 잠금과 에스컬레이션으로 후속 행동을 보장한다.
